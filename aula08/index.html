0Preparar o ambiente

Abra o terminal (Atividades → Terminal) e instale as ferramentas. Algumas vêm do repositório extra EPEL.

# repositórios padrão
sudo dnf install -y procps-ng sysstat psmisc nano cronie openssh-server tcpdump

# EPEL (stress e nmon) — Rocky/AlmaLinux: epel-release; RHEL: veja a nota abaixo
sudo dnf install -y epel-release
sudo dnf install -y stress nmon dstat
RHEL com assinaturaSe epel-release não for encontrado: sudo subscription-manager repos --enable codeready-builder-for-rhel-9-$(arch)-rpms e depois sudo dnf install -y https://dl.fedoraproject.org/pub/epel/epel-release-latest-9.noarch.rpm. No RHEL 9, o dstat é fornecido pelo pacote pcp-system-tools.

Crie uma pasta para guardar os arquivos gerados e defina o nano como editor padrão:

mkdir -p ~/aula08 && cd ~/aula08
export EDITOR=nano

1Utilizando o /proc slide 22

O /proc é um pseudo-sistema de arquivos: os “arquivos” são gerados pelo kernel na hora em que você lê. Quase todas as ferramentas desta aula leem daqui.

1.1 Recursos do sistema

ls /proc | head -30                 # números = PIDs; nomes = informações do sistema
cat /proc/meminfo | head -10        # memória
grep -E 'MemTotal|MemAvailable|SwapTotal' /proc/meminfo
cat /proc/loadavg                   # carga: 1, 5 e 15 min, executando/total, último PID
head -5 /proc/stat                  # contadores de CPU desde o boot
grep -c processor /proc/cpuinfo     # número de CPUs (compare com nproc)
grep -m1 'model name' /proc/cpuinfo
cat /proc/uptime                    # segundos ligado e segundos ocioso
head -5 /proc/vmstat                # contadores de memória virtual
cat /proc/diskstats | head -5       # contadores de disco
cat /proc/net/dev                   # bytes e pacotes por interface de rede

1.2 Um processo específico: /proc/<pid>/status

Use o PID do seu próprio shell (variável $$):

echo $$                                   # PID do seu shell
ls /proc/$$                               # tudo o que o kernel sabe do processo
grep Vm /proc/$$/status                   # memória do processo
grep -E 'VmSize|VmRSS|VmHWM|Threads|State' /proc/$$/status
tr '\0' ' ' < /proc/$$/cmdline; echo      # linha de comando que iniciou o processo
ls -l /proc/$$/fd                         # arquivos abertos
CampoSignificado
VmSizeToda a memória virtual usada
VmRSSMemória física (RAM) em uso
VmHWMPico atingido pelo RSS (high water mark)
ThreadsNúmero de threads do processo

1.3 Parâmetros do kernel em execução

Arquivos em /proc/sys são parâmetros que podem ser lidos (e, com sudo, alterados):

cat /proc/sys/kernel/hostname
cat /proc/sys/vm/swappiness         # tendência a usar swap (0 a 100)
sysctl vm.swappiness                # mesma informação via sysctl
✓ Checkpoint: anote quanto de RAM seu shell usa (VmRSS) e o load average atual.

2ps — Process Status slide 23

ps                          # só os processos do terminal atual
ps -e | wc -l               # quantos processos existem
ps -ef | head               # todos, formato Unix (com PPID)
ps aux | head               # todos, formato BSD (com %CPU e %MEM)
ps aux | grep sshd          # procurar um processo
ps aux --sort=-%mem | head -6   # os 5 que mais usam memória
Estilos de opçãoBSD sem hífen (aux) ou Unix com hífen (-ef). Use um estilo por vez.

3top, uptime e free slide 24

3.1 top

top -d 5            # atualiza a cada 5 s — saia com q
top -i              # esconde processos ociosos — saia com q
top -n 3            # 3 atualizações e termina sozinho
top -b -n 1 > top.txt     # modo batch, salva em arquivo
head -15 top.txt

Dentro do top: 1 mostra cada núcleo, P ordena por CPU, M por memória, q sai.

3.2 uptime

uptime
nproc               # compare o load average com o número de CPUs

Load average perto do número de CPUs é normal; bem acima indica sobrecarga.

3.3 free

free -m             # em MB
free -k             # em KB
free -t -m          # com linha de totais
free -m -s 2 -c 3   # repete a cada 2 s, 3 vezes
DicaOlhe a coluna available, não só free: o Linux usa memória livre como cache e devolve quando precisa.

4vmstat slide 25

vmstat 2 5          # 5 amostras a cada 2 s
vmstat -S M 2 3     # em MB
vmstat -a           # memória ativa/inativa
vmstat -s | head -15   # formato de tabela
vmstat -d           # estatísticas de disco
lsblk               # descubra o nome da sua partição (sda1, vda1, nvme0n1p1…)
vmstat -p sda1      # troque sda1 pelo nome que apareceu no lsblk
GrupoColunas
procsr esperando CPU · b em espera ininterrupta
memoryswpd swap usada · free livre · buff/cache
swapsi do disco para a RAM · so da RAM para o disco
iobi blocos recebidos/s · bo blocos enviados/s
systemin interrupções/s · cs trocas de contexto/s
cpuus usuário · sy kernel · id ocioso · wa espera de E/S

5Pacote sysstat slide 26

5.1 iostat — disco e E/S

iostat              # CPU + E/S
iostat -c           # só CPU
iostat -d           # só disco
iostat -p sda       # só um disco (use o nome do lsblk: sda, vda, nvme0n1…)
iostat -x 2 3       # estendido, 3 amostras a cada 2 s

5.2 mpstat — processadores

mpstat              # todos os processadores
mpstat -P ALL       # cada CPU separadamente
mpstat 2 5          # 5 coletas a cada 2 s

5.3 pidstat — por processo

pidstat -u 1 3      # uso de CPU
pidstat -r 1 3      # memória e page faults
pidstat -d 1 3      # E/S (pode exigir sudo)
pidstat -p $$ 1 3   # um PID específico (o seu shell)

6dstat e nmon slide 27

6.1 dstat — visão combinada

Cada comando fica rodando: pare com Ctrl+C.

dstat 5             # a cada 5 s
dstat -c            # CPU
dstat -m            # memória
dstat -d            # disco
dstat -n            # rede
dstat -cmdn 2 5     # tudo junto, 5 amostras a cada 2 s

6.2 nmon — Nigel's performance Monitor

nmon                # modo interativo

Dentro do nmon: c CPU, m memória, d disco, n rede, t processos, q sai.

nmon -f -s 5 -c 12          # grava 12 capturas a cada 5 s em arquivo
ls *.nmon                    # saída: host_data_hora.nmon

7Experimento: 1 minuto de monitoramento slide 28

Plano: 60 s com amostras a cada 5 s → 60 / 5 = 12 coletas. Você vai precisar de dois terminais.

7.1 Terminal 1 — gerar carga

cd ~/aula08
free -m                                  # confira se há ~2 GB disponíveis
stress -m 2 --vm-bytes 1G -t 50s         # 2 workers de memória, 1 GB cada, por 50 s
Pouca memória?Se o available do free -m for menor que 2500 MB, use --vm-bytes 256M.

7.2 Terminal 2 — monitorar (logo em seguida)

cd ~/aula08
nmon -f -s 5 -c 12                       # grava o nmon em arquivo
vmstat 5 12 | tee vmstat_experimento.txt # mostra e grava ao mesmo tempo

7.3 Ver o resultado

ls -lh ~/aula08
cat vmstat_experimento.txt
grep -i "^MEM," *.nmon | head            # linhas de memória gravadas pelo nmon
✓ Checkpoint: no vmstat_experimento.txt, a coluna free caiu durante o stress e voltou depois? Houve si/so (swap)?

8tcpdump slide 29

Capturar pacotes exige sudo. Primeiro descubra o nome da sua interface de rede (no Red Hat costuma ser ens33, enp0s3, eth0…):

ip -br addr                    # interfaces e IPs
sudo tcpdump -D                # interfaces que o tcpdump enxerga
IF=ens33                       # troque pelo nome da sua interface

Em outro terminal, gere tráfego para ter o que capturar: ping -c 20 8.8.8.8 ou curl -s https://www.redhat.com > /dev/null.

sudo tcpdump -c 10 -i $IF               # só 10 pacotes
sudo tcpdump -n -c 10 -i $IF            # só IPs, sem DNS
sudo tcpdump -n -c 5 -i $IF icmp        # filtro: só ping
sudo tcpdump -n -c 5 -i $IF port 443    # filtro: só HTTPS
sudo tcpdump -c 50 -i $IF -w pacotes.pcap    # salvar em arquivo
tcpdump -r pacotes.pcap | head          # ler o arquivo
tcpdump -tttt -r pacotes.pcap | head    # com data e hora

Cada linha mostra: horário, tipo de pacote, origem e porta, sentido (>), destino e porta.

9Crontab slide 30

systemctl status crond --no-pager     # o serviço do cron precisa estar ativo
sudo systemctl enable --now crond     # se não estiver
crontab -l                            # lista os agendamentos (provavelmente vazio)
EDITOR=nano crontab -e                # abre o crontab no nano

No nano, acrescente a linha abaixo (roda a cada minuto), salve com Ctrl+O → Enter e saia com Ctrl+X:

* * * * * uptime >> $HOME/aula08/uptime.log
crontab -l                    # confira
sleep 125; cat ~/aula08/uptime.log   # espere 2 minutos: deve ter 2 linhas
crontab -r                    # remove o agendamento ao final
CampoValores
minuto · hora · dia do mês · mês · dia da semana0-59 · 0-23 · 1-31 · 1-12 · 0-7 (dom = 0 ou 7)
Atalhos@reboot @hourly @daily @monthly @yearly
Exemplo do slide0 0 * * * nmon -f -s 120 -c 720 -m /home → coleta de 24 h começando à meia-noite

10SSH slide 31

sudo systemctl enable --now sshd      # liga o servidor SSH
systemctl status sshd --no-pager
ssh $USER@localhost uptime            # executa um comando "remoto" na própria máquina

Na primeira conexão, responda yes e digite sua senha. Depois, teste com a máquina de um colega (peça o IP com ip -br addr):

ssh USUARIO@IP_DO_COLEGA uptime
ssh USUARIO@IP_DO_COLEGA free -m
Combinecron + ssh + ferramentas de monitoramento = coleta automática em vários servidores.
