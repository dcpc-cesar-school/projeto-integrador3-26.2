Projeto Integrador — AED + Infraestrutura de Software

Cada equipe pega uma aplicação que já está desenvolvendo em outra disciplina, aplica nela estruturas de dados, ordenação e busca, coloca tudo em containers com um fluxo de DevOps e constrói um módulo de monitoramento com um painel em três níveis: hardware, containers e serviços.

Sobre o projeto

O projeto integra duas disciplinas do 3º período em um único produto. As aplicações variam de equipe para equipe, mas o módulo de monitoramento é comum a todas: a aplicação de cada equipe entra como o serviço monitorado. Assim, AED aparece no código real (as estruturas de dados sustentam o coletor e o painel) e Infraestrutura de Software aparece na forma como tudo roda, é entregue e é observado.

O trabalho é construído aos poucos, uma prática por aula. Cada tutorial gera uma peça que vai para o repositório da equipe no GitHub e é reaproveitada na etapa seguinte, até a demonstração final na AV2.

As duas disciplinas no projeto

AED

Estruturas de dados, ordenação e busca

  • Base própria de estruturas: lista, pilha, fila, fila circular, hash e árvore binária de busca
  • Ordenação (insertion, selection, merge, quick) e busca (sequencial e binária)
  • Aplicação no código da equipe e no monitor
  • Análise de complexidade e testes
Infraestrutura de Software

Containers, DevOps e monitoramento

  • Containers (Docker/Compose; Kubernetes como bônus)
  • Fluxo de CI/CD com GitHub Actions
  • Threads e concorrência: evitar race condition
  • Memória: evitar o OOM Killer e registrar eventos
  • Métricas coletadas com comandos do SO

Arquitetura

Stack tecnológica

A stack é definida por cada equipe e registrada no README do repositório, com uma justificativa curta para cada escolha (linguagem, framework do backend, interface, bibliotecas de teste). Ela será apresentada no checkpoint de 05/11. Seja qual for a escolha, ela precisa permitir:

  • implementar as próprias estruturas de dados, ordenação e busca (sem usar as coleções prontas da linguagem nas partes avaliadas);
  • criar threads e usar mecanismos de sincronização;
  • executar comandos do SO ou ler /proc para coletar métricas;
  • rodar em containers Linux e ser testada em um pipeline de CI no GitHub Actions.
